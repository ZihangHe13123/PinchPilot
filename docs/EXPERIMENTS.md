# 数据采集与实验协议

## 先做试采

先让三位组员分别跑通相机和应用内任务。相机支架、镜头位置、坐姿和前臂支撑尽量固定；记录系统、相机、画面分辨率、距离、光线和惯用手。避免把画面里的其他人误当作参与者。

参与者自行选择编号（P01 等），征得同意，只采任务需要的关键点。程序不会保存或上传相机视频；JSONL 仍属于参与者动作数据。发布课程数据前确认可共享范围，身份映射另存并不交付。

## 四种标签

| 标签 | 要录什么 | 如何减少标注错误 |
|---|---|---|
| open | 舒适分开拇指/食指、自然定位；不必最大张开 | 倒计时结束前摆好，录制期间保持类别 |
| pinch | 拇指/食指指尖捏合，可小范围移动掌部 | 记录多次独立捏合，不只复制一段 |
| scroll | 食指中指伸直、无名指小指弯曲的 V 手势 | 包含小幅上下移动与不同角度 |
| other | 握拳、伸手取物、放松等不打算触发的动作 | 故意避免前三类的典型姿势；模糊片段重录 |

这是「可观察手形」分类器，other 不等于已经解决所有无意识意图。两种意图可能拥有相同的手形，仅靠当前静态特征无法保证区分。

界面选择参与者、场次、人工标签、每段时长后录制。每段有 3 秒准备时间。缺失手部的帧会保存为空关键点，用于统计掉帧；不用于手形分类训练。当前没有自动剪掉错误标签或过渡动作，发现不一致应重录/人工删除相应整段。不要拿规则输出生成标签再声称验证了 ML。

### 建议规模

试采：3 人 × 4 类 × 每类 3 次 × 每次约 6 秒，先检查数据和分类混淆。正式阶段在可招募条件下争取 6–10 人、每人至少两个独立场次、不同距离/光线；每类有多次重复。它们是建议规模，不是统计充分性的保证。

程序要求至少 2 个分组且训练/测试都覆盖所有类别，满足这个最低运行条件并不代表样本量足以支持广泛结论。帧数不是参与者数，报告同时列人数、场次、独立动作段与帧数。

## 训练与划分

默认按参与者分组固定随机种子，留出约四分之一分组。只在训练分组拟合；保存的模型就是留出评估时的模型。程序会拒绝重复 episode ID。独立场次模式按「参与者/场次」成组，只能支持新场次结论。

第一次固定划分后，后续不要根据测试成绩选择种子或阈值。需要调参时在训练参与者中再分验证组；最终测试者保持未见。当前自动报告是一次分组留出的结果，尚无多折、统计检验或独立最终测试管理器，不能重复调整后继续称其为独立最终测试。

比较 RF 与 SVM 时保持相同人员、标签、特征与划分。报告有默认规则、模型原始输出、按运行时阈值拒识后的模型三组指标。macro F1 在真实标签集合上计算，uncertain 计为对应类的漏判；混淆矩阵包含所有预测类。RF 投票分数和 SVM margin 不同，均未进行概率校准。

关键点距使用宽高比修正后的二维坐标和掌部尺度归一化。该特征降低平移/尺度影响，不能保证对任意旋转、遮挡、透视和逆光不变。手型颜色/光线问题也可能出在预训练跟踪器，而不是上层分类器。

## 三组实验

### A. 手形判定

同一留出分组上比较固定规则、RF、SVM。输出每类 precision/recall/F1、macro F1、拒识覆盖率、混淆矩阵、跟踪失败比例；按参与者/环境分析典型失败。当前自动报告提供汇总，逐人/逐环境分析可依据原始录制和分组列表补做。

### B. 个人校准与点击稳定

用专门的校准场次采 open/pinch；在另一个场次完成测试。不要把测试动作反过来校准阈值。对照设置至少包括默认规则/个人规则，以及稳定定位开/关。UI 可恢复默认阈值、加载个人校准；每次任务日志会保存配置。

稳定定位开关目前只切换捏合位置锁定/拖动起点补偿，手掌参照与平滑在两组都存在。因此结果只能归因于该开关控制的机制，不能声称完成了全部滤波组件的消融。

### C. 实际交互

「点击与拖拽实验」每轮 8 个目标，分别做点击与拖拽；既支持应用内手势，也支持鼠标/触控板。手势任务不会额外向系统注入输入。先练习一轮，再正式测试；在参与者之间交叉安排条件顺序，减少熟练效应。保持窗口大小、屏幕/DPI、目标大小和顺序一致；必要时记录使用的鼠标或触控板类型。

主要指标：任务完成时间、命中数、失误数、未完成任务比例、每目标耗时、主观舒适度（例如 1–7 分，方向写清楚）和疲劳变化。任务 JSONL 有 metadata、每次尝试和 summary，取消也会保存 completed=false。当前程序不会自动采集问卷，请单独记录。

v0.2 的小幅模式可加入三种条件：60% 固定映射、30% 固定映射、30% + 休息后恢复。前两组比较范围大小，后两组比较重新接管机制；保持识别器、捏合阈值、稳定定位开关、窗口大小和相机布置一致。需要时再加入 20%，不要只用“原版 vs 全部新功能”来归因。切换设置会结束当前任务，正式比较应分别开始新一轮并交叉安排顺序。

任务和离散事件日志保存完整 EngineConfig，任务另存初始指针位置。当前没有自动计算手掌路径长度、重新接管次数或问卷分数。30%/60% 是相机归一化坐标的范围，不是厘米；要讨论实际手臂位移，还需距离标定或独立测量。用户目前报告“识别准确，但手掌来回移动累”，可用于确定设计问题，不能充当改进后的量化结论。

误触率需要额外的自然动作时间段：预先声明哪些时段不应产生点击，按 **误点击次数 / 非操作分钟** 统计。仅凭 other 类准确率不能推导在线误触率。推理耗时也不是从动作开始到屏幕反应的端到端延迟，需要另外设计计时/视频对齐。

## 数据文件与复现

每段 JSONL 第一行为 metadata：schema、participant、session、episode、label、label_source、feature_version、UTC 创建时间。后续是递增时间戳、21 个 xyz 关键点或空列表、宽高比、handedness。时间戳是本进程单调时钟，用于同段时序，不能跨电脑直接比较绝对值。

MediaPipe handedness_score 表示左右手分类置信度，不代表每个关节的可见性，也不作为手部追踪质量分数。

```sh
uv run pinchpilot inspect-data
uv run pinchpilot train --output reports/experiment_01 --model forest --seed 42
uv run pinchpilot replay data/recordings/某段.jsonl --output reports/replay.json
```

离线 replay 只生成事件文件，不注入鼠标。单一 pinch 片段如果没有先出现 open，就不会触发按下，这是状态机的预期行为；它不能替代连续交互测试。演示/自动化测试的合成帧只用于工程检查，不纳入研究数据与性能表。

最终实验包应包含：去身份化数据、收集条件说明、划分/随机种子、模型和依赖锁、原始指标与任务日志、失败案例、分析方法。当前源码交付包故意不包含私人数据和实际研究结论。
