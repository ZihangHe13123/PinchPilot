# PinchPilot 0.11.0 — Windows 组内测试版

适用：Windows 10/11，Intel/AMD 64 位电脑，普通摄像头。
本包自带 Python、依赖和手部模型，无需安装 Python、uv 或下载模型。
包名为 `PinchPilot-0.11.0-Windows-x64.zip`，建议预留至少 2 GB 可用空间；
压缩包大小和 SHA-256 以本次归档清单为准。
目标为普通用户权限下的主屏幕；Windows ARM、32 位和多屏切换尚未覆盖。
本版默认使用「兼容定位 · 平移＋转腕」，**无需方向校准**。
Windows 真机启动、相机、系统输入和日常手感仍待组员测试；包内容和哈希检查不等于真机验收。
旧 v0.8.1 ZIP 保留原样，本说明对应独立的 v0.11.0 归档。

## 开始使用

1. 右键 ZIP →「全部解压」。建议解压到自己可写的短路径，例如 D:\PinchPilot。
   不要在压缩包预览里直接运行，也不要只复制 Start.cmd。
2. 双击 Start.cmd，确认窗口标题为 0.11.0。第一次打开可能稍慢，后台黑色窗口用于启动和记录错误，
   正常退出请关闭 PinchPilot 界面。
3. 点「启动相机」。关闭其他占用相机的软件；在 Windows 设置的摄像头隐私页面，
   允许桌面应用访问摄像头。相机选错时可在「展开手感设置」中切换编号。
4. 前臂放在桌面或扶手上，先只露出控制手，等窗口确认锁定；画面正常后，点「启用鼠标控制」。
   展开手感设置可确认定位方式为「兼容定位 · 平移＋转腕」，不需要先做三步腕动校准。
5. 随时按 Esc 停止鼠标控制；关闭程序会停止相机和控制。

刚启动时相机和鼠标控制都关闭，需要手动开启。设置不会记住「启用控制」状态。
首次使用本包是全新配置。若自行保留旧设置，旧腕动配置会首次切换到兼容定位并提示；
原位置配置保留选择，可手动切到兼容定位。原灵敏度、抗抖、按钮设置和旧校准参数保留，
旧方向参数不参与兼容定位；以后主动选回旧角度实验，就会记住该选择。

## 手势速查

| 操作 | 动作 |
|---|---|
| 移动 | 食指先分开，拇指＋中指轻捏住，整手平移或自然转腕；手停光标停 |
| 左键 | 食指＋拇指短捏，松开食指 |
| 双击 | 到位后连续食拇短捏两次，中间明确松开；也可松中指锁住光标再点 |
| 右键 | 食指分开，无名指先离开拇指片刻，再与拇指轻捏 |
| 拖拽 | 食指＋拇指保持捏住，等约 0.30 秒，再保持捏合移动；松食指放下 |
| 滚轮 | 食指＋中指做 V，无名指和小指弯曲，拇指分开；保持片刻后上下轻移 |
| 结束滚动 | 收回 V；重新捏拇指＋中指恢复移动 |
| 换位续拖 | 拖拽中保持食拇捏合，只松中指换手位，再捏中指继续 |
| 停止控制 | Esc，或窗口里的「停止控制」 |

滚动期间光标固定，上移向上滚、下移向下滚，停止移动后滚动停止。
「展开手感设置」里的灵敏度滑条向左更慢；可先试 0.50×，仍快则用 0.30×。
松开滑条后应用，更改设置会暂停控制，需再点「启用鼠标控制」。
右键、拖拽和滚轮有独立开关，滚动速度也可以单独调节。
兼容定位固定使用精细滤波，旧移动模式选择保留供切回位置对照使用。
本模式隐藏两种旧校准面板，不需要寻找「6 秒静止校准」或「三步腕动方向校准」。
详细比较动作和边界见 [COMPATIBLE_TRIAL.md](COMPATIBLE_TRIAL.md)。

## 建议先测这几项（约 5 分钟）

1. 分别整手平移、前臂有支撑时小幅转腕，再混合两种动作，检查是否同向、是否突然跳动或断触。
2. 打开普通浏览器窗口：移动到链接附近，左击几次；在记事本里用双击选词，检查漏点或误点。
3. 在页面空白处右击，检查是否重复弹出菜单或误触左键。
4. 在记事本测试拖选文字，放开食指后应放下；测试拖拽时按 Esc 能否松开。
5. 用 V 手势上下滚动网页，检查方向、速度、收回手势后是否停住。
6. 手暂时移出画面，确认光标停住、按键释放；回来先分开食指，再捏中指接管。
   最小化 PinchPilot 后检查控制和边缘提示，另一只手入镜时检查是否干扰。
7. 记录常见 FPS、推理耗时、灵敏度和体感。先短时试用，再决定是否继续。

首次测试请用普通权限的浏览器/记事本。不要以管理员身份运行 PinchPilot；
管理员窗口、UAC 安全桌面不是本次测试目标。

## 启动不了 / 找不到 DLL

- 双击 Diagnose.cmd。它会检查依赖、模型推理、Windows 只读接口和 3 秒演示窗口。
  不开相机、不操作系统鼠标、不更改你的日常手感设置。
- 诊断结果在 reports\diagnostics\ 下，启动错误在 reports\startup\ 下。
- 如果提示 MSVCP140、VCRUNTIME140 缺失，手动运行 prerequisites\VC_redist.x64.exe，
  按微软安装器提示安装后重试。此安装器不会自动运行，部分电脑可能需要管理员批准。
- 如果系统拦截，先确认收到的是组内原始完整测试包；不需要关闭杀毒软件。
- Windows N/KN 如缺少媒体组件，按系统提示安装对应的 Media Feature Pack 后重试。
- Demo.cmd 可只看合成手势演示，用于区分界面启动问题与摄像头问题。

## 反馈怎么发

填写同目录 FEEDBACK.txt。附上问题大致发生时间、复现步骤、窗口显示的 FPS，
以及 reports\desktop_trials\ 中对应的 trial_*.jsonl。启动故障附上对应诊断文件夹。
日志不保存摄像头图片/视频、手部关键点、输入文本或应用标题，不自动上传。
诊断包含系统版本、依赖版本和可能带用户名的本机文件路径；发送前可自行查看。
诊断中的 demo-window.png 只截本程序生成的演示窗口，不截桌面。

试用设置在 data\desktop-settings.json；卸载时退出程序、保留需要的反馈文件后，
删除解压文件夹即可。向下一位组员分发时使用原始 ZIP，避免把已有的 data、reports 和个人反馈一起发出。
保留 runtime、models、docs、source、prerequisites 及启动文件一起解压。
