# 项目定位与推进顺序

## 建议题目

**PinchPilot: Minimal-Motion Hand Interaction for Stable Desktop Control**

中文定位：**面向少动作、小幅度的稳定手势操控系统**。

2026-09-21 根据用户反馈更新目标：在普通 RGB 摄像头、macOS/Windows 环境下，以尽可能少的启用、复位、切换和纠错动作，以及尽可能小的掌部位移和指部动作，稳定完成定位、点击、拖拽与滚动。成功率、误触率、响应时间和任务完成时间作为约束，同时独立测量主观费力度。

这是可验证的研究问题，尚不是已证实的产品优势。任务定位为部分桌面交互的补充；是否能长时间替代鼠标、是否减轻不适，需要真实参与者实验。

“少”首先指完成同一任务所需的动作次数，不是单纯减少分类标签；“小”同时考虑手掌和手指，不能把运动从一个部位转到另一个部位后仍宣称整体减少。单击、双击和拖拽优先复用捏合的事件状态。完整定义和候选比较见 [少动作、小幅度设计](superpowers/specs/2026-09-21-minimal-motion-design.md)。

用户已明确前臂悬空，并在缩小映射范围后的讨论中继续报告累。下一步先验证支撑姿势下的可见性，记录动作成本；当前 30%＋休息后恢复作为主要基线。新增计量、候选控制和时序 CNN 尚未实现。

v0.3 单指轻弯/停留在用户试用中出现严重晃动、难以操作，现暂时搁置并保留失败记录。v0.4 拇中中点定位与抗抖获得用户“移动舒服、点击不够灵敏”的定性反馈；v0.5 保留移动处理，按用户建议改为食拇点击，支持松中指后锁住位置再点，[试用说明](TRIPOD_DEMO.md)。当前先验证两条点击路径、误触与点击带偏，再比较动作成本；正式稳定性与舒适度实验、Windows 真机仍待完成，拖拽/滚动另做设计。

v0.6 阶段：用户认可 v0.5，并选择拇无名指右键；v0.6 补充右键、食拇按住拖拽、锁定换位，以及应用内右键/拖拽任务。移动参数保留，左键完整点击改在松开时完成。先体验这些动作，再按用户条件推进数日真实桌面测试版；滚动仍未扩展到该模式。完整操作见 [本轮体验](RIGHT_CLICK_DRAG_TRIAL.md)。

最新：用户认可右键和拖拽后，明确要求成为可操控鼠标、带必要数据与开关的工具。v0.7 已实现独立桌面测试窗口、Mac/Windows 输出接入、后台 Esc/心跳松键、设置持久化及本地性能/按钮记录；日常使用见 [桌面测试版](DESKTOP_TRIAL.md)。不改变既有默认移动处理，正式真人实验和 Windows 硬件验收仍待进行。

## 与课程要求的对应

依据 `PRS-PatternRecognitionSystems-Practice-Module 7.0 - FT.pdf` 第 9–10 页，课程允许实用模式识别系统，示例中直接包含 hand gesture recognition。要求至少覆盖列出的四个方面中的三个。

| 课程方面 | 本项目如何体现 | 需要交付的证据 |
|---|---|---|
| Supervised / unsupervised learning scenarios | 人工标注 open、pinch、scroll、other | 数据定义、标注过程、划分方式 |
| Machine learning / Deep learning techniques | 已有 RF/SVM 工具；计划加入轻量时序 CNN；复用 MediaPipe 视觉模型 | 自有数据、训练脚本、模型、独立测试、同一任务上的基线比较 |
| Intelligent sensing / sense making techniques | 相机采集、关键点、归一化、时间确认到可执行交互 | 实时演示、延迟与故障处理测量 |
| Hybrid ML / Ensemble approach | Random Forest 本身是树集成，可分析与 SVM 的差异 | 实际模型比较，不能仅把规则外壳称为集成学习 |

前三项形成明确对应。ML/DL 在原要求里是同一条，不能把二者拆成两条凑数。复用 MediaPipe 必须标明；自有贡献需要体现于数据、分类器、交互设计和实验，而不能只展示一个库调用。具体评分由教师判断。

第 15–16 页要求：可运行系统、数据集、最终报告、源代码/模型/支持材料、10–15 分钟视频、两次汇报的幻灯片；每人另交 1–2 页个人报告并完成 peer review。团队最终交一个 ZIP，个人报告除外。

## 与 Pawvis 的关系和可做的亮点

参考版本：Pawvis commit `039e6d8ede814cb943532b841e6c78f83fba1f62`。它的默认点击是食指下压；已有校准、点击稳位、拖拽处理、注意力门控和 DTW 自定义手势模板。不要写成「Pawvis 只有简单阈值，没有学习或个性化」。

补充调研：2026-09-21 查阅仓库当前 README，还介绍了指尖参照点与停留点击；此处是当日页面描述，非本机实测。单指和停留本身不能作为本项目区别于 Pawvis 的新发明，差异要由小幅操作的实验结果支持。

本项目独立实现，采用 VR 风格的拇指/食指捏合选取，并以跨平台的真实交互评测作为交付重点。捏合本身已有广泛先例，也不是学术首创。适合课程的贡献是：

1. **把动作成本量化。** 对同一任务记录掌部路径、指部活动、启用/复位/纠错次数，验证小幅操作是否反而增加重复动作。
2. **把小动作识别作为模型问题。** 在相同误触约束下比较规则、RF、时序 CNN 对较小动作的漏触与延迟，分析不同参与者和场次的失败。
3. **把稳定与舒适落到任务。** 固定识别器比较控制方式，固定控制方式比较模型；同时记录完成时间、误操作、抖动和主观费力度，并与鼠标/触控板对照。
4. **同一核心覆盖两种桌面系统。** 记录不同相机、分辨率、DPI 和权限路径的验收结果。

时序 CNN 作为下一阶段候选，需要连续标注数据和规则失败证据，尚不承诺优于规则。个人适配作为扩展。隐式意图推断、三维缩放、复杂手势词表和多模型融合不进入当前主线；学习组件之外保留明确的停止、按下与释放机制。

## ML 难度与具体顺序

第一版 ML 难点主要在数据与评估，而非搭网络。21 点由预训练模型提供；当前从中取 12 个几何特征训练 RF/SVM。下一阶段的时序模型增加过去一段轨迹；与其比较的 RF 也提供窗口统计。先按人/场次划分再生成窗口，更多相邻帧不会自动等于更多独立样本。

| 顺序 | 工作 | 完成标准 | 当前状态 |
|---|---|---|---|
| 1 | 需求、规则交互、退出条件 | 明确单手/主屏/点击/拖拽/滚动 | 已实现 |
| 2 | 共用 GUI、模型推理、平台接口 | 能预览、回放、解释权限；真人操作另验 | 工程检查已跑，已有用户定性反馈；Windows 真机待验 |
| 3 | 支撑姿势与动作计量 | 三位组员检查相机可见性，基线点击/拖拽各完成 2 轮 8 目标；记录动作与费力度 | 现有目标任务可用，动作计量/分段待补 |
| 4 | 控制方式候选 | 固定识别器，与 v0.2 30% 基线比较动作次数、幅度、质量 | 单指暂搁置；三指已获定性认可，v0.7 进入桌面试用 |
| 5 | 连续数据与模型实验 | 人工标注动作过程，规则/RF/时序 CNN 同任务分组评测 | 静态 RF/SVM 工具已实现，时序工具待做 |
| 6 | 正式交互对照 | 从独立试采冻结质量标准，报告动作成本、稳定性、费力度与取舍 | 待试采后冻结并开展 |
| 7 | 双平台验收与正式交付 | 启动说明、数据、模型、评测、报告、视频可复现 | 待硬件验收和正式材料 |

## 三人分工建议

- A：交互与系统。摄像头、映射与复位方式、状态机、Mac/Windows 适配、故障验收。
- B：数据与学习。连续标注与质检、RF/时序 CNN、分组和误差分析、可复现实验。
- C：动作计量与用户实验。动作分段、掌部/指部幅度、任务顺序、费力度和图表、汇报材料。

三人都参与采集与代码理解；每人维护自己的贡献记录，个人反思依据实际工作撰写。

## Proposal 可用摘要（草稿）

本项目拟构建一套可在 macOS 和 Windows 使用的普通摄像头手势交互系统，研究如何以较少的辅助动作和较小的手部活动幅度稳定完成桌面操作。系统复用预训练手部关键点模型，使用人工标注数据比较固定规则、Random Forest 与轻量时序 CNN，并由确定性状态机管理点击、拖拽及按键释放。项目将以已有原型为基线，分别评估指针映射与复位方式、小幅动作识别、支撑姿势下的交互表现，通过相同任务记录动作次数、掌部与指部幅度、完成时间、误操作及主观费力度。主要交付包括跨平台原型、去身份化数据及标注说明、模型与训练脚本、动作成本和稳定性评测工具、对照结果及实验报告。
