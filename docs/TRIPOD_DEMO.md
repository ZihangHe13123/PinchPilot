# 拇中定位 Demo：左右键与拖拽

日常真实鼠标已在 [桌面测试版](DESKTOP_TRIAL.md) 开放；v0.8 共用连续灵敏度滑条和 V 滚动识别。本页保留研究界面的操作与诊断说明，真实滚轮使用桌面入口。

v0.6.0：**拇中捏住定位；食拇短捏松开左击，保持后移动可拖拽；拇指＋无名指轻捏右击。** 到位后可以松中指锁定位，再做左/右键。食指、无名指坐标不参与指针移动。普通相机用关键点距离估计靠近，并不直接检测皮肤碰撞。快速体验顺序见 [右键与拖拽试用](RIGHT_CLICK_DRAG_TRIAL.md)。

用户认可 v0.5 的移动与食拇点击，随后选择拇无名指右键并要求补充拖拽。保留定位映射、滤波和抗抖参数。为支持拖拽，左键改为接触确认时按下、分开时释放，完整单击在松开时完成；不再像 v0.5 一碰就发出整对按下/释放。v0.3 单指方案仍因严重晃动而搁置，主观反馈和合成检查均不等于量化结论。

## 启动和基本操作

退出旧窗口，双击 `launch_tripod_mac.command`（Mac）或 `launch_tripod_windows.cmd`（Windows），再点击「启动摄像头」。右侧模式为「拇中定位 · 左右键与拖拽」，沿用原三指入口。命令行：

```sh
uv run pinchpilot gui --interaction tripod
# 只看合成动作与界面，不打开相机：
uv run pinchpilot gui --interaction tripod --demo
```

1. 前臂放在桌面或扶手上，让相机看清三个指尖；拇指和中指轻轻接触即可，不必用力挤压。
2. 食指先留在外侧，保持拇中捏合约 0.12 秒。当前捏合点对齐原指针位置，随后移动捏合点定位。
3. **左键：**食指接近拇指时先冻结指针，接触约 0.06 秒后按下并变色；分开确认后释放，完成一次单击。短捏即可，保持不会连点。食指不必碰中指。
4. **拖拽：**在物体上食拇捏住，等待进度环满（按下后默认约 0.30 秒），再保持捏合、移动拇中点。松食指放下。等待期间的合指位移被丢弃，进入拖拽时从原光标位置开始。
5. **右键：**食指保持分开，无名指先离开拇指片刻，再轻捏拇指。接近时冻结、接触约 0.10 秒后右击一次，松开无名指恢复定位。一直蜷着无名指不会在启动时直接右击；食拇按住期间忽略右键。
6. **松中指锁定位：**左/右键仍可触发。拖拽时若食拇仍捏着，保持按下但停住位置；重新捏住中指约 0.12 秒后可继续拖。食拇分开会放下，不必先重新捏中指。
7. **完全暂停用 Esc 或「暂停手势」。**丢手、过期、换手、明显跳变或修改设置会结束按住，练习中标作取消，不计成成功。恢复后须重新用拇中接管。

如果尚未按下就在松中指时同时合拢食拇，会提示先分开再捏合。食指与无名指同时接近、无法区分新左/右键时也要求先分开；不在一次动作里同时发两种按钮。已经按下再松中指会保持按下，不重复点击。

在「点击与拖拽实验」分别选择点击目标、右键目标、拖拽到圆环，每轮 8 个。右键任务仅用右键算成功；拖拽须从橙色方块拿起，到目标环松食指。这个研究入口仍只输出到应用内，真实桌面控制及滚轮改用桌面测试入口。这些新动作不录入旧捏合四分类训练集。

## 抗抖怎么调

默认活动范围为画面宽高各 30%，定位使用拇中指尖中点的画面坐标；不会逐帧除以掌部尺度。中值处理抑制孤立跳点，速度自适应低通降低噪声，径向死区抑制静止漂移；越过死区时只跟随超出的部分，避免突然跳到原始输入位置。食指靠近时的冻结是另一道独立处理。

| 设置 | 先怎么试 | 代价 |
|---|---|---|
| 移动灵敏度 | 从 1.00× 开始，偏快可逐步调低；原 40% 档等于 0.75× | 0.10×～2.00× 连续调整；更慢需要更多手部位移或换位，默认滤波不变 |
| 抗抖强度 | 标准；仍飘再试强 | 强档也会抑制有意的小移动，并不能免费提高精度 |
| 食拇接触 | 先保持默认；靠近却不点击时可试宽松 | 宽松可能在实际触碰前判定，严格可能漏触 |
| 右键触碰 | 默认；拇无名指接触困难时单独试宽松 | 不影响左键阈值，仍可能提前判定 |
| 拖拽等待 | 默认 0.30 秒；可试 0.20/0.50 秒 | 更短更快，也更容易把短按时的挪动当成拖动 |
| 滚动速度 | 标准；真实翻页过快时调慢 | 独立于指针灵敏度；研究目标任务没有滚动成功率评分 |

轻/标准/强的死区半径分别为归一化屏幕坐标 0.003/0.008/0.014，不是厘米。范围和抗抖强度是不同参数；正式比较一次只改一个。修改设置会结束任务，需要重新开始一轮。

## 先做一次 8 秒静止记录

点击「记录 8 秒静止抖动」，有 2 秒准备。支撑前臂、捏住拇中、移开食指，保持舒适静止；相机画面保持手部可见。程序记录新相机帧上的原始映射点、处理后点、状态和配置，保存到 `reports/jitter/probe_*.json`，不保存视频。

记录结束显示两条轨迹各自相对均值的 RMS 散布和有效样本信息。暂停、冻结点击、丢手及原始点超出屏幕范围不进入稳定定位样本；数据不足或中途取消会明确标记。计时器在相机停顿期间不重复采样旧结果。该记录依赖使用者按提示静止，不提供真实运动或点击意图真值，也不是准确率。

完成静止记录后，分别用“保持中指捏合”和“松中指锁定”做一轮 8 目标点击。先保持移动范围和抗抖档位不变，观察点击是否更容易、是否带偏、重新捏中指是否跳动，记录误点和漏点。静止时很稳但小目标挪不过去，说明抗抖代价过大；大幅降低移动灵敏度后才稳，也要记录增加的动作成本。任务结果另存 `reports/tasks/`。

日志中的 `contact` 在 v0.5 起表示食指—拇指距离，v0.4 表示食指到拇指/中指的较大距离。比较时按 `app_version` 分组，不能把两种含义混算；锁定与点击状态不计入静止定位样本。

## 仍要验证的边界

三指靠拢可能遮挡，触碰的机械联动仍可能移动拇中捏合点。程序用估计三维距离减少仅二维重叠造成的混淆，但深度也来自模型，不能保证实际接触识别。[MediaPipe 坐标说明](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python#handle_and_display_results) 是坐标归一化的依据；本项目没有训练新的手部网络。

随机小抖动、缓慢漂移和有意微调不总能仅凭位置区分。合成噪声检查特意包含独立噪声和相关漂移，后者仍可能明显保留，不能据前者的改善宣布真人晃动已经解决。真实静止记录和交互反馈用于下一轮调整。

如果前臂放下后相机看不到手，应调整机位；保持捏合本身是否疲劳也要实测。Windows 共用同一套引擎与 PySide 界面，本轮未做 Windows 硬件验收。

工程验证：`uv run python scripts/check_tripod.py`，生成左/右键保持中指与松中指四种条件、拖拽条件各自的合成八目标结果，以及两类已声明噪声和界面截图，位于 `reports/verification/tripod-<版本号>/`。本机有 v0.4 历史记录时还会逐帧核对连续定位；旧证据保留。这些数据不混入真人记录或训练集。
