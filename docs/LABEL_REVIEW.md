# 标签检查说明

录制时生成的标签是草稿。每人把自己的 3 段录制逐段确认一遍，再抽查另一位组员的录制。自己的每段约 10 分钟，抽查每段约 2 分钟。

## 打开

先在 PinchPilot 文件夹和数据仓库文件夹里各运行一次 `git pull`，然后在 PinchPilot 文件夹里运行：

```
uv run pinchpilot ml-review C:\Projects\PinchPilot-data\recordings --annotator P02
```

`--annotator` 后面填你自己的编号。窗口上方的列表里，自己的录制排在前面；选自己的是“检查”，选别人的是“抽查”。

## 窗口里有什么

- 左边是录下来的手的关键点，循环播放当前这一段。
- 右边每根手指一行。**曲线**是拇指尖到这根指尖的距离，越低越近。曲线下面的**色带**是标签：绿色是接触，灰色是未接触，斜纹是故意不给标签的边界。
- 最上面一行的橙色块是按住空格的时间。

## 检查自己的录制

1. **先对时间。** 用 → 翻到一段“食指点拇指”，看绿色色带是否落在曲线的低谷里。绿色可能整体偏左，也可能整体偏右：摄像头画面比真实动作晚一点，所以空格常常显得偏早；反应慢的时候又会偏晚。拖动第一个滑块，往右是把空格标记提前，往左是推后，让绿色大致落进低谷。这个值整段录制共用，先调好再开始逐段看。
2. **逐段看。** 对得上按 Enter 通过，对不上按 X 作废。作废的段不进入训练，不用犹豫。
3. 全部看完后点「完成并保存」。
4. 把窗口提示的两个文件（`.labels.json` 和 `.review.json`）上传到数据仓库里这段录制所在的文件夹。

怎样算对得上：

| 这一段 | 应该看到 |
|---|---|
| 需要按空格的 | 每个低谷下面有一段绿色，没有低谷的地方没有绿色 |
| 捏住、松开 | 中指曲线捏住时低、松开时高，色带在曲线变过去之后才变 |
| 靠近但不碰 | 曲线有起伏，色带一直是灰色 |

这些情况按 X 作废：漏按或多按了空格、动作做错了、手出了画面（左边显示“这一帧没有检测到手”）、曲线乱跳。

另外三个滑块一般不用动。如果很多段的色带都在曲线变过去之前就变了，把「提示出现后留空」调大。**改动任何滑块后，之前通过的段会退回未看状态**，需要重新看一遍。

进度在每次按键后自动保存，可以随时关掉，下次从没看的那一段继续。

## 抽查另一位组员的录制

用同一条命令，在列表里选对方的录制。对方检查完并上传之后才能抽查。

程序固定抽 6 段，约十分之一，其中至少一半是需要按空格的。每段按 Enter 同意或 X 不同意，不同意时在输入框里写一句原因。结果自动保存成 `….crosscheck.你的编号.json`，上传到同一个文件夹。

对方再打开自己的录制时，会在那一段看到你的意见；对方修改并重新保存后，旧的抽查结果不再算数，需要再抽查一次。

## 按键

| 键 | 作用 |
|---|---|
| Enter | 通过 / 同意，并跳到下一段没看的 |
| X | 作废 / 不同意 |
| ← → | 上一段、下一段 |
| 空格 | 暂停、继续播放 |

点时间轴可以把播放位置移到那一刻。

## 这种检查能做到什么

- 没有保存视频，所以检查时看到的是关键点和距离曲线，不是真实的手。它能发现时间没对齐、漏按、动作做错，但不能证明指尖真的碰到了。
- 时间只能整段统一移动，不能单独改某一次按键。个别对不上的段只能作废。
- 标签始终只来自屏幕提示、空格和你的通过或作废。程序不会按曲线自动改标签，因为模型的输入也是这些关键点，那样做等于让模型给自己出题。
