# 小幅移动与休息后恢复

依据用户此前“允许尽可能推进”的授权，以及本轮实际试用反馈“幅度动作大了感觉还是很累”，在既定的小幅动作目标内改进映射。现有规则版已被用户报告好用；保留它作对照，不声称已经完成舒适度实验。

## 方案选择

- 采用可选的小幅位置映射：相机宽高各 30% 覆盖主屏，另提供原有 60% 与更敏感的 20%。30% 使相同屏幕位移所需的归一化画面位移约减半；它不等于实测肌肉负担减半。
- 配合手势休息：握拳/离开画面结束按下并停止光标。重新分开拇指食指、完成启用确认后，以当前手位对齐原光标位置，避免恢复时跳动。拖拽结束也对齐最后光标位置。
- 单独的速度控制或自动推断疲劳需要额外交互学习与验证，留待真实数据支持后再做。

## 模块与边界

EngineConfig 增加布尔 reanchor_on_open；纯引擎默认仍为原始模式，桌面程序默认选择 30% + 休息后恢复，便于保留旧回放的含义。映射在归一化屏幕坐标中进行，维护一个偏移量；新配置使用旧模型不改变特征版本。

界面提供范围选择和恢复选项，预览虚线显示当前有效映射区域。切换配置先释放系统输出、结束当前任务并回到预览。启用真实输出时读取当前系统光标，作为恢复起点。只读取主屏坐标，不能偷偷移动光标。Mac 与 Windows 共用映射，位置读取仍在各平台适配层。

录制时禁用映射设置变更。个人校准的加载/恢复仅改变捏合阈值，保留用户的移动范围。任务与事件日志包含范围与恢复开关；恢复偏移不应解释为相机重新检测出的视觉信息。

## 验证

验证 60%/30% 位移比例、首次定位、握拳后换手位、丢手/换手恢复、按下时休息、拖拽释放、边界限制、GUI 模式切换释放、校准不覆盖映射、两个平台只读光标 API。保留既有状态机测试。离屏截图检查控件及虚线显示，不重启用户当前正在使用的实例，不自动打开第二路相机。

交付后由用户退出旧实例、重启后实际体验。是否减少疲劳、20% 是否过敏感、不同姿势是否仍准确均待实测；不把合成回放作为人体舒适度证据。
