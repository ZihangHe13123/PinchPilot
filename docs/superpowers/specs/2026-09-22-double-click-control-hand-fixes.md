# 双击和控制手修复

用户反馈从未成功双击，随后补充另一只手入镜会干扰操作。沿用已认可的拇中定位、食拇点击、右键、拖拽及滚动，不调整移动滤波或增添新的手势。

## 双击

macOS 的 CGEventCreateMouseEvent 默认点击次数是 1，旧适配器每次创建事件后直接发送，因此第二次仍是单击。只读原生验证发现，设置 kCGMouseEventClickState 后 AppKit 才能读到 clickCount=2。

输出层按系统 NSEvent.doubleClickInterval()、同一按键、4 个逻辑点以内的位置和完整按下/释放序列生成 1、2、3 次点击标记；对应的释放必须保持同样计数。实际拖动超出容差、超时、左右键切换、滚动或停止会打断序列。立即输出单击，不新增等待或冻结移动，不改全局系统设置。输出失败不提交新状态，清理松键保留对应计数。Windows 继续由系统将 SendInput 序列解释为双击。

## 控制手

旧模型配置 num_hands=1 且始终取下标 0，无法在第二只手出现后选择原控制手。改为最多检测 2 只手，再按左右手类别、掌部位置连续性和短暂稳定确认选择控制手。自动模式先只露出一只手，稳定 3 帧后锁定；相机运行期间丢失也不解除左右手锁定。控制手缺失、分类不明确、同类候选冲突或双掌过近时输出缺手帧，让既有引擎释放按键并重新接管；恢复需稳定 3 帧。丢帧不沿用旧坐标。

桌面界面增加自动 / 只用右手 / 只用左手和锁定状态。只保存选择偏好；切换选择先停止相机和控制，重新启动相机后生效，自动模式重启相机可重新选手。左右手类别并非生物身份识别，严重遮挡或分类错误仍需真人验证；不宣称双手交叉时能保证跟踪身份。

## 验证与交付

覆盖两次快速点击、超时、不同位置、拖动、左右键交错、滚动、清理与失败重试，并将 30 FPS 合成手势通过真实引擎接到原生事件对象，拦截发送后用 AppKit 检查点击计数。覆盖双手排序变化、另一只手独占画面、返回原手、低置信度和掌部接近，以及 UI 选项持久化和停止行为。

交付源码修复 v0.8.2，保留现有 v0.8.1 Mac 和 Windows 归档。离屏界面和无硬件模型验证不代替真人双击、双手遮挡测试；不重启用户正在运行的程序或发送系统输入。
