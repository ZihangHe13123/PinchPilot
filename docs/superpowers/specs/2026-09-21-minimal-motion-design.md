# 少动作、小幅度的稳定手势操控

状态：用户于 2026-09-21 将项目目标调整为“用尽可能少和小的动作来稳定操控”，并追加“最懒情况下只用一根指头交互”的候选要求。随后授权两个单指 demo，偏好主动点击；v0.3 已实现应用内轻弯与停留候选，见 [具体设计](2026-09-21-single-finger-demos-design.md)。真人效果、其他候选控制方式、动作计量和时序 CNN 仍待实施或验证，不代表已有实验结论。

## 研究目标

在普通 RGB 摄像头、macOS/Windows、单手单主屏条件下，完成相同的定位、点击、拖拽和滚动任务时，减少必要动作以外的启用、复位、切换和纠错动作，并降低手掌位移及手指活动幅度，同时维持可接受的成功率、误触率和响应时间。

“尽可能”表示比较可实现方案的取舍，不声称已找到全局最优。动作次数、掌部位移、指部运动分别报告，不用一个任意加权分数隐藏代价。动作更少、更小也不直接等于疲劳更低，舒适度单独测量。

用户已报告规则交互主观上准确，但长时间操作累，并明确前臂仍悬空。支撑姿势下的相机可见性是下一轮试采的前置检查；新识别模型不能替代机位与支撑条件的调整。

## 三个研究问题

1. 在相同任务与识别器下，改变指针映射及复位方式，能否同时减少位移和辅助动作，而不增加错误或完成时间？
2. 在手部动作较小、姿势较放松时，自训练识别器能否在相同误触约束下减少漏触？
3. 前臂支撑后，上述方案是否仍可被普通摄像头稳定跟踪，用户费力度是否改善？

## 范围与候选方案

| 方案 | 用途 | 要验证的取舍 |
|---|---|---|
| v0.2 固定映射＋握拳复位 | 主要基线；默认 30%，保留 20%/60% 的受控比较 | 小范围可能放大抖动或增加复位；不能仅凭映射比例宣布整体成本降低 |
| 有支撑的小范围输入＋速度相关指针增益 | 优先研究的候选；先固定输入参照点，再单独比较掌部与指尖参照 | 较快动作跨较大距离、较慢动作精调的设计是否真的减少纠错；当前速度自适应滤波不等于已实现该增益 |
| 小偏移控制光标速度 | 第二候选，前一方案出现频繁复位时再试 | 能否少复位，同时仍容易停在小目标上；持续偏移不应被视作“零动作成本” |

先验证支撑姿势与镜头能否兼容，再一次改变一个因素。保留移动、捏合、拖拽、滚动和休息的基本操作，优先复用同一种捏合的按下/保持/释放，不为了操作数量把单击、双击、拖拽都拆成独立手形类别。

减少不必要的模式切换是候选设计目标；明确停止、丢手释放和重新接管检查仍由状态机执行。完整系统的动作成本应包括这些动作，不能从统计中删除。多屏、全桌面目标吸附、眼动、RL、自研手部检测网络不进入本轮主线。

## 单指交互候选

“单指”定义为只主动操作一根食指，前臂与掌部尽量获得支撑，其他手指自然放松。MediaPipe 仍需足够可见的手部结构；这不承诺仅露出孤立指尖也能稳定追踪。单指数量不是费力度指标，仍按实际位移、关节活动、持续保持、等待和纠错测量。

定位候选使用食指相对掌部的运动，先校准舒适姿势及可用范围。相对参照旨在减少掌部平移的影响，效果须验证；它不能自动消除透视、手部旋转或跟踪抖动。先在应用内目标任务验证定位和点击，现有捏合模式作为完整交互基线保留。

| 点击方式 | 最小操作 | 主要取舍与验证 |
|---|---|---|
| 指尖定位＋停留点击 | 食指定位后停住，倒计时结束触发一次；没有额外屈指点击动作 | 最省点击动作的首个候选，但增加等待，需测试停下阅读/休息时的误触；停住不重复点击，离开确认区域后才重新准备 |
| 指尖定位＋轻微屈指点击 | 定位后食指短暂轻弯、恢复 | 主动触发候选；屈指与向下定位可能混淆，须验证点击期间稳位及小幅动作识别，不能直接同时把指尖位移当移动和点击 |

停留必须有可见倒计时、移开取消和明确暂停方式；只在已启用的操作状态计时，丢手或姿势失效取消待触发动作。静止既可能表示选取，也可能表示休息，因此不能把“稳定不动”直接等同于点击意图。首个原型只在应用内运行，评测后再接系统鼠标。

拖拽与滚动可以通过单指的模式选择或按下锁定来扩展，但会增加操作或等待，不能先承诺完整鼠标功能都同样省力。首个单指候选只要求定位、左击和暂停；通过后再对拖拽/滚动做独立设计与比较。停留时间必须计入完成时间和响应延迟；如果仅以较慢操作换取更少动作，报告该取舍。

停留计时本身不需要 CNN。自训练模型可研究小幅主动屈指、定位、放松和过渡过程的可观察差异；模糊输入允许拒识，状态机仍负责点击次数与释放。

单指轻压、指尖定位和停留点击已有先例，不作为本项目首创。2026-09-21 查阅的 [Pawvis 当前 README](https://github.com/alexandriax/pawvis) 已介绍这些相关能力；这属于文档描述，未进行本机产品实测。[Apple Dwell 文档](https://support.apple.com/guide/mac-help/use-dwell-mchl437b47b0/mac) 也说明停留可触发点击、拖拽与滚动。本项目的可验证贡献仍是动作成本、稳定性、小幅识别及双平台评测。

## 模型分工

- MediaPipe 继续提供预训练手部追踪，权重保持不变。
- 保留固定规则和 RF/SVM 工具；正式主比较收敛为规则、RF 与一个轻量时序 1D-CNN。SVM 可作补充，不要求同时增加 MLP、LSTM 和 Transformer。
- 对时序任务，RF 使用同一历史窗口的统计特征，与 CNN 保持相同标签、人员划分和可见时间范围。单帧 RF 对照可用于分析时间信息的作用。
- CNN 学习可观察的手形与动作过程，不声称从相同外观中直接读出用户意图，也不将光标移动坐标变成离散分类。
- 当前整段单标签录制可用于静态模型；时序研究需补充连续动作及转换时刻的人工标注。先分参与者/场次，再生成窗口。运行时只用当前及过去帧，不等待未来帧；触发延迟单独评估。
- 正式比较绘制动作幅度与漏触、误触之间的关系。幅度太小导致关键点信息不可用时，记录感知失败，不强迫分类器给出确定操作。

## 指标与测量方法

| 目标 | 主要指标 | 计量边界 |
|---|---|---|
| 少 | 每个任务的总动作段数；另列启用、复位、模式切换、纠错次数 | 一次持续捏合算一个动作段，逐帧预测及重复鼠标 move 事件不算独立动作；中断后重做计入成本 |
| 小：掌部 | 累计掌部路径和最大活动范围，相对该场次固定的掌部尺度归一化 | 包含任务期间复位、纠错的位移；使用相同机位、距离、采样与离线处理；不是厘米，也不是肌肉负担 |
| 小：手指 | 预先指定关节的活动角度及拇食指相对距离变化 | 使用同一组关节和定义；不能通过把掌部运动转移给手指就宣称总运动减少 |
| 稳 | 任务完成率、误点/漏触、目标停留期间光标抖动与点击偏移 | 区分手形分类、事件触发和最终任务成功，不用一个 accuracy 概括全部 |
| 快 | 任务完成时间、动作到事件的触发延迟及 p95 | 保留时间标注依据；模型推理耗时不当作端到端延迟 |
| 省力 | 相同任务时长下的主观费力度，0 为不费力、10 为极费力 | 同时记录支撑方式和持续控制时间；该问卷不是客观肌肉负担测量 |

动作分段和辅助动作类别由任务提示或人工核验确定，不拿待评估模型自己的分类输出当真值。一个动作可以附带复位/纠错标签，但汇总总次数时只计一次。成功和未完成任务均保留总量，另报告每成功目标的成本，避免用低完成率换取“少动作”。

跟踪中断期间的位移不可见，不跨丢手间隔连线补算，也不按零运动处理。记录有效覆盖率；超出预先规定丢手容忍量的轮次不能参与完整路径下降结论，但仍保留为任务失败/感知失效记录。对静止抖动与路径长度使用统一采样与计量滤波，不能让不同候选各用有利于自身的处理方式。

## 验证设计与判断规则

1. 组内试采先使用 3 位组员。检查前臂支撑时手指可见性、掉手、静止抖动和可用动作范围，记录实际机位；不能为了完成条件要求参与者继续维持不舒服的姿势。
2. 主对照固定为 v0.2 的 30%＋休息后恢复，记录完整配置及版本。60% 原始映射用于额外分析，不能只对较弱基线展示改进。
3. 每位组员在基线和一个候选条件下，各完成 2 轮 8 目标点击；支持拖拽的条件另各完成 2 轮 8 目标拖拽，先练习，交叉安排条件顺序。单指首个原型只参加点击比较，功能覆盖范围另列，不宣称完成整套鼠标对照。滚动需另做固定内容与距离的任务；目前尚无自动滚动任务验收器。
4. 用试采建立测量噪声及可接受误差、延迟、完成时间范围，在正式测试前冻结数值、划分和配置。当前不虚构“99% 准确率”或“疲劳下降一半”的验收标准，也不依据正式测试结果反向修改标准。
5. 正式实验按参与者配对报告各项指标及差值。成功依据是：在冻结的质量范围内，动作次数和幅度都下降；若只改善一项，明确报告为取舍，不写成两项都改善。基线辅助动作已为零时，目标是保持零并改善幅度，不能计算零分母降幅。
6. 模型实验固定映射、支撑姿势与状态机；交互实验固定识别器。调参使用训练/验证数据，正式测试者保持未见；有个人校准时另设独立校准片段。

试采流程跑通与研究假设成立是两个不同结果。样本少时报告描述性结果与限制，不能因平均值略有改善就宣布对所有用户有效。紧急停止、按键释放等工程检查失败时，先修复再继续试用。

## 推进顺序与交付

1. 将目标、指标和基线同步到项目计划与实验协议。
2. 确认支撑姿势下的可见性；补动作计量、人工分段和连续序列标注工具。
3. 使用现有规则与基线采集组内数据，量化动作、位移、错误与费力度；先试单指主动屈指，同时用停留点击对照，逐步选择控制候选。
4. 采集跨人员/场次数据，训练 RF 与时序 CNN，完成动作幅度和错误率的对照。
5. 固定方法后做双平台验收、正式交互实验和报告。

交付包括跨平台原型、人工标注数据及数据说明、模型与可复现训练脚本、动作成本与稳定性评测脚本、原始日志、对照图表、失败案例、报告与视频。已有版本的 58 项工程检查不构成新目标已经实现的证据。
