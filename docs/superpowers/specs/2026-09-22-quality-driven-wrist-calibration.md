# 质量驱动的腕动校准

用户试用v0.10.0无法通过校准，且没有看到失败原因。源码确认错误仅在窗口底栏，校准区域恢复为“尚未校准”，日志没有失败原因。当前历史摘要因此不能确定该次失败的具体阈值。旧实现方向采集还筛选无关的指尖接触条件，并在固定12秒内强制换步。

用户明确要求：给出提示和姿势参考，数据足够才通过，不按倒计时推进。按此实现三步质量驱动流程，维持既有掌部几何及方向稳定性要求，不靠全面放宽阈值宣称校准成功。

- 三步为中立、向右、回中立后向上。每步要求最近36帧内有至少30个有效掌姿，最新30个有效姿态稳定，间隔连续；只有通过才进入下一步，无阶段倒计时或总截止时间。
- 向右/向上的示范角域仍为估计8–35度，两方向夹角45–135度，姿态波动参考上限2度。逐帧和拟合结果均须满足约束，避免保存不可完成后续校准的边界姿态。
- 当前步骤不合格时保持等待，滑动窗口自动淘汰坏数据；此前已通过步骤保留。第三步明确先回到中立（估计偏转≤5度），再向上。
- 掌部朝向独立于点击接触条件，方向采集不要求食指/中指/无名指满足捏合阈值。提示自然放松、保持相近常用手形；校准期间系统输入始终关闭。
- 当前界面显示阶段、箭头/角度参考、有效帧进度、稳定性或拒绝原因。循环姿势示意动画对应当前步骤，动画时间不参与通过判定，前臂固定、转动围绕腕部。
- 主手势区在校准时显示校准说明，不显示可能由自然弯指触发的PRESSED等预览手势文案。最终失败/取消原因在校准面板持久显示，失败时滚动到提示。
- 本地仅记录步骤计数、拒绝原因及角度统计，不保存图像、关键点或桌面内容；关闭记录时不写日志。旧有效校准失败后保留，成功后仍需手动启用鼠标。
- 相机真正停流、来源/模式切换和用户取消仍结束采集并保持系统输入关闭。不能用过期画面完成校准。

验证覆盖：不随时间推进、低帧率仍能收够样本、坏姿势恢复、自然手指接触不影响姿态结果、步骤保留、回中立引导、完整真实校准器到UI持久化、错误提示和日志、动画离屏渲染与关闭时停止。

用户另要求最终与基础模式合并。当前先保留可对照的两个定位来源，后续统一控制入口，研究平移和转腕组合、可信度与连续过渡；不在校准修复中偷偷加入未经实测的自动切换。
