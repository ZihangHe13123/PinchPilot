# v0.9.0 移动调优与静止校准试用

日期：2026-09-22。本轮先改非 ML 控制处理，保持现有手势。代码和合成对照已完成，是否更舒服、更好点中目标还需真人体验；长期路线见 [FUTURE_PLAN.md](FUTURE_PLAN.md)。

## 启动与回退

先按 Esc 停止，退出旧窗口，再用 `launch_desktop_mac.command` 或 `launch_desktop_windows.cmd` 启动源码版，确认标题为 **0.9.0**。已交付的 Mac/Windows **v0.8.1 ZIP 未更新**，不含本轮功能及 v0.8.2 修复。Windows 真机验收仍未完成。

「展开手感设置 → 移动模式」中有三个选项：

| 界面选项 | 主要变化 | 怎么看待它 |
|---|---|---|
| 原版 · 对照（classic） | 保留 v0.8.2 的移动处理 | 熟悉的回退基线；静止更稳，但细小修正可能被抑制 |
| 精细 · 小幅微调（precise） | 更小的屏幕尺度软死区、较快的滤波，改进屏幕边缘的反向恢复 | 优先试小目标和反向微调；静止抖动可能更多 |
| 自适应 · 实验（adaptive） | 在精细处理上随速度改变增益，慢速细调、快速跨越 | 同样手部位移不一定得到同样屏幕位移，需要适应 |

全新配置默认精细；已有旧版设置但缺少模式字段时迁移为原版，保留此前手感，需要主动选精细试用。已保存的新版模式会恢复。切换模式先关闭控制，之后手动重新启用；不会修改已在运行的旧实例。

拇中捏住定位、食拇短捏点击、保持拖拽、拇无名指右键、V 手势滚动和松中指冻结均不变。灵敏度、抗抖、滚动速度仍可分别设置。完整操作见 [DESKTOP_TRIAL.md](DESKTOP_TRIAL.md)。

## 先不校准，比较三种移动方式

保持相同机位、支撑姿势、灵敏度与抗抖档。若已保存校准，先记下状态并用「清除静止校准」建立未校准对照；不需要删除设置文件。

1. 原版中做短距离移动、停在小图标旁、轻轻反向修正，再试大范围移动和靠屏幕边缘后反向。
2. 换精细，重复相同任务；主要感受“是否更容易动一点”“停下是否还拖尾”“为了压住抖动是否更紧张”。
3. 换自适应，重复同样任务；检查慢速修正与快速移动的衔接，是否需要频繁重新定位。
4. 在偏好的模式补测点击、双击、右键、拖拽和滚动，确认改善移动时没有破坏原手势体验。

先只改模式，避免同时修改所有参数而不知道哪项起作用。可随时选原版回退。普通试用不要求持续抬手；前臂应得到支撑。

## 再比较静止校准前后

静止校准适用于精细和自适应，不是 ML 训练。它根据本次姿势下的静止波动调整抑制范围，不能自动知道哪些小动作是你有意做的。

1. 启动实时相机，选精细或自适应；支撑前臂，让控制手清晰可见。
2. 点「6 秒静止校准」，程序先关闭鼠标控制并释放按键。拇中轻捏、食指和无名指移开；准备1秒、采集5秒，保持捏合点尽量不动。
3. 查看结果。「采集时波动 X 逻辑像素」只描述这次采集，不是当前实时读数或识别准确率。
4. 无论完成、取消或失败，都不会自动恢复系统输入；需要时手动点「启用鼠标控制」，再重新捏合接管。
5. 重复校准前的小目标、静止、正向与反向修正。如果抖动小了但微调更难，用「清除静止校准」撤销，或切回原版。

样本不足、采样不连续、持续漂移或波动过大时会拒绝应用，保留原有参数。程序也检查采集前后稳健中心的漂移，避免把缓慢有意移动当成静止噪声。换机位、支撑姿势或距离后，旧估计可能不再适合，可重新采集。

标准抗抖档下，精细/自适应的未校准软死区半径为2个逻辑屏幕坐标单位，校准基础半径最高4；软死区位于速度增益之前。这个4不是所有档位的最终输出上限：抗抖「强」档还乘1.75，可达到7。更强抑制可能吃掉细微移动，校准不能保证精细定位一定改善。

## 本轮合成对照告诉了我们什么

以下数字来自真实 `TripodEngine` 处理生成的关键点：30fps、1920×1080逻辑坐标、span=0.30、标准抗抖档、相同输入序列、每段先静止预热3秒。没有打开相机、没有发送系统输入；它们不是人的准确率、疲劳或端到端延迟。

| 指标 | 原版 | 精细 | 自适应 |
|---|---:|---:|---:|
| 静止白噪声输出 RMS / px | 0.000 | 2.817 | 1.553 |
| 相关漂移输出 RMS / px | 0.745 | 9.730 | 5.351 |
| 9.6px小修正的正向响应 / px | 0.000 | 7.600 | 4.180 |
| 同段反向响应 / px | 0.000 | 5.600 | 3.080 |
| 阶跃达自身最终位移90% / ms | 133.3 | 66.7 | 66.7 |
| 靠边反向首次1px响应 / ms | 1000.0 | 66.7 | 66.7 |

在这些输入下，新模式能响应原版吞掉的小修正，边缘反向恢复也更快；但静止波动增加。原版的零白噪声输出同时伴随零小修正响应，不能只凭“最稳”选择它。自适应改变增益，阶跃实际位移与另两模式不同；响应按自身最终位移计算，不能把它偏离固定映射终点当成准确率问题。

校准使用独立seed、独立时间段，未在测试轨迹上拟合。一次白噪声校准得到7.779px波动估计、151个有效样本，并触及标准档4单位基础半径上限：

| 校准前→后 | 精细 | 自适应 |
|---|---:|---:|
| 白噪声输出 RMS / px | 2.817→1.905 | 1.553→1.048 |
| 相关漂移输出 RMS / px | 9.730→8.848 | 5.351→4.867 |
| 小修正正向响应 / px | 7.600→5.600 | 4.180→3.080 |
| 小修正反向响应 / px | 5.600→1.600 | 3.080→0.880 |

另一次相关漂移校准被实际接口拒绝，未应用，也没有填写校准后数字。校准降低部分静止波动，却也缩小小修正响应；这正是需要真人比较的取舍。

可复现命令：

```sh
uv run python scripts/check_motion_tuning.py
```

完整条件、seed、配置、轨迹和拒绝结果保存在 `reports/verification/motion-0.9.0/motion-comparison.json`，简表在同目录 `motion-comparison.md`。经典六组轨迹与 v0.8.2 的固定参考一致；机制检查也覆盖有限坐标、屏幕边界、孤立尖峰和反向恢复。最终工程验收见 [VALIDATION.md](VALIDATION.md)。

## 反馈与数据

优先记录：模式、是否校准、灵敏度/抗抖档、姿势和机位，以及“哪个操作更舒服或更难”。特别区分静止抖动、起动不灵、停下拖尾、方向反转延迟、点击牵动和跟踪丢失。可记出现问题的大致时间，方便对照本地性能日志。

桌面日志仍只保存性能、事件和校准估计摘要，设置只保存参数；本次静止校准关键点只在内存处理，不写入日常日志。不保存图像、视频、桌面内容、输入文本或应用标题，不上传。离线对照报告中的完整轨迹是脚本生成的数据，不能混入真人训练集。
