# PinchPilot 后续打磨计划

更新日期：2026-09-22。本文保存已讨论的长期路线；不把计划、自动测试或合成演示写成真人体验结论。当前源码为 **v0.9.0**，以 v0.8.2 原版移动方式作对照；本轮非 ML 调优代码与合成对照已完成，待真人试用。

## 1. 两条目标并行推进

**个人日用目标：** 用尽可能少、尽可能小的动作稳定操作电脑，让前臂能获得支撑，减少反复抬手、重新接管和纠错。先在浏览、阅读、普通窗口操作中达到愿意持续使用，再扩展到精细选择、跨屏和长时间操作。不先承诺全面替代鼠标，也不以“手势能识别”作为舒适度验收。

**课程研究目标：** 建立可复现的模式识别实验，回答哪些失败来自跟踪、控制映射、动作判定或使用姿势，以及个人校准和学习模型分别能改善什么。工程完成度与模型效果分别报告；课程交付边界以原始任务书和 [PROJECT_PLAN.md](PROJECT_PLAN.md) 为准。

产品与研究共用采集、回放、对照和版本记录。稳定的非 ML 版本既能先解决体验问题，也能成为后续 ML 的公平基线；不为了增加“工作量”引入没有可验证收益的复杂模型。

## 2. 既有基线与能力边界

| 项目 | v0.8.2 已实现 | 尚不能据此宣称 |
|---|---|---|
| 操作 | 拇中定位、食拇点击/双击/拖拽、拇无名指右键、V 手势滚动 | 已达到鼠标级精度或日用舒适度 |
| 移动稳定 | 三帧中值、速度自适应低通、软死区；接近点击时冻结，松开后重新锚定 | 已找到每个人、每个距离和摄像头的最优参数 |
| 控制手 | 左右手选择、自动锁定、位置连续性检查；不明确时暂停 | 双手交叉、严重遮挡时仍可可靠辨认同一只手 |
| 运行保障 | Esc 停止、过期帧保护、按键释放、重新接管 | 所有平台、应用权限层级和长时间运行均已验收 |
| 跟踪 | 复用 MediaPipe 预训练 Hand Landmarker；请求 640×480、30fps | 每台设备实际达到30fps，或完整输入延迟等于推理耗时 |
| 研究工具 | 人工标签关键点录制、几何特征、RF/SVM、按参与者/场次划分评估 | 当前桌面三指控制已经使用自训练模型 |
| 数据 | 日常记录保存本地性能、状态及事件发送摘要 | 日志自带准确率、用户意图标签，或可直接训练点击模型 |
| 平台 | 共用 Python/PySide6 核心，Mac/Windows 输入适配，主屏操作 | Windows 真机验收完成，或已经支持跨屏 |

当前已有静态分类工具使用 `open / pinch / scroll / other` 标签，与完整三指交互状态不等价；个人阈值校准也不等于模型微调。自动测试证明的是被覆盖的逻辑和接口行为。

已交付的 Mac、Windows **v0.8.1 便携包保持原样留档**，不包含 v0.8.2 修复或本轮调优。源码版本、正在运行的进程和交付压缩包版本要分别核对。

## 3. 优先顺序与阶段验收

| 阶段 | 核心工作 | 进入下一阶段前应拿到的证据 |
|---|---|---|
| A：建立体验基线 | 固定任务、姿势和设备，记录失败位置、耗时、误触及疲劳 | 同一版本、同一设置的可重复结果，明确最影响使用的两三项问题 |
| B：非 ML 移动调优 | 对照经典、精细、自适应指针；检查死区、增益、滤波和延迟 | 合成轨迹解释取舍；真人对照确认改善，点击/拖拽无明显退步 |
| C：统计个人校准 | 测静止噪声、舒适移动范围和捏合差异，生成可恢复的个人参数 | 新场次复测仍有收益；错误姿势/样本不足不会生成误导参数 |
| D：小幅捏合时序 ML | 明确失败场景与人工事件标签后，训练轻量模型与规则比较 | 独立测试上的误触、漏触、响应时间和任务表现支持采用模型 |
| E：日用与平台工程 | 恢复体验、手身份连续性、多屏/DPI、权限与打包、长时间试用 | Mac/Windows 真机按清单验收；出现问题能复现、退回稳定版本 |

A 与 B 先行；可靠停止/松键的缺陷随发现随修。E 中的体验和平台工作可以与研究并行，不必等待 ML。

## 4. 本轮 v0.9：先试非 ML 调优

**状态：代码完成、合成对照完成，待真人试用。** 具体操作与数据见 [MOTION_TUNING_TRIAL.md](MOTION_TUNING_TRIAL.md)，工程记录见 [VALIDATION.md](VALIDATION.md)。

- **经典模式：** 保留已有移动方式，作为可切回的对照。
- **精细模式：** 已加入屏幕尺度的较小软死区和较快滤波；桌面新配置默认使用，原有手势不变。
- **自适应模式：** 已加入有界、随速度平滑变化的增益，保留实验标记；软死区在增益前处理，避免低速增益进一步放大起动门槛。
- **非 ML 静止噪声校准：** 已实现准备1秒、采集5秒的统计估计；校准先关闭输入，完成、失败或取消均不自动恢复。标准抗抖档的基础半径上限为4个逻辑屏幕坐标单位，强档仍乘倍率、可达到7；校准不是神经网络训练。
- **合成轨迹对照：** 已用确定性白噪声、相关漂移、小幅正反向、阶跃、孤立尖峰和边缘恢复比较三模式；另用独立seed/时间段校准后复测。记录输入、参数、输出轨迹和真实拒绝结果，均注明合成来源。

合成结果显示精细模式能响应原版吞掉的9.6px小修正，也显示其未校准的静止波动更多。独立校准降低部分静止波动，但仍削弱微调，不能保证更舒适或更精确。相关漂移校准被拒绝，未填入校准后效果。三种模式的名称是取向；当前默认精细用于试用，是否作为长期默认要由真人对照决定。

## 5. 非 ML 仍有很大改进空间

### 5.1 把“稳”和“细”分别测量

v0.8.2 的死区作用于归一化屏幕坐标，固定比例会随屏幕坐标宽高改变实际尺度。例如，横向坐标宽度1920时，`.008` 对应15.36个坐标单位的半径；这不是指针必然每次跳15个像素，但可能影响起动和反向细调。后续应明确逻辑坐标、物理像素和显示缩放的关系，再比较按屏幕尺度定义死区、噪声自适应死区和不同速度下的增益。

当前已使用 One Euro 家族的速度自适应低通。重点是调参数、坐标单位和滤波组合，而非仅换一个算法名称；更强平滑通常也带来更明显的跟随延迟。调校方法参考 [One Euro 作者说明](https://gery.casiez.net/1euro/)，实际收益由本项目实验决定。

### 5.2 减少定位与点击的相互牵动

保留用户已接受的拇中定位、食拇点击，优先调整接近、按下、松开和重新锚定的过渡。后续可对照掌部多个相对稳定点、指尖中点以及二者融合；掌部并不必然优于指尖，应以遮挡、细调和点击落点偏移决定。

快速双击、慢速点击、短暂停留和拖拽要分别测试。减少等待时间可能提高响应，也可能增加误触；不能只降低所有确认阈值。失去可靠跟踪时继续保留确定性的松键和暂停逻辑。

### 5.3 先测整条延迟，再优化摄像头

分别记录读帧、预处理、推理、界面取结果、手势确认及输出阶段。当前读帧后的时间戳不包含所有曝光和驱动缓冲时间，完整“手动起来到屏幕响应”还需独立测量。

比较实际支持的帧率/分辨率、相机位置、照明、采集与推理调度、预览开销。MediaPipe 的视频模式会阻塞当前调用，实时流模式支持异步回调但繁忙时可能忽略新帧；换模式本身不保证更低端到端延迟，需记录实际丢帧与结果年龄。[MediaPipe 官方 Python 文档](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python)

### 5.4 使用姿势也是系统设计的一部分

前臂持续悬空的问题不能仅靠滤波解决。建立“手能被看清且前臂有支撑”的机位和舒适范围检查；需要时调整摄像头角度或位置。降低动作幅度时，同时检查是否放大抖动、增加手指紧张和重新接管次数。休息、物理鼠标接管及恢复应容易理解、可预测。

## 6. ML 应该提升什么

**首选研究问题：** 在较小的捏合幅度、不同使用者和拍摄角度下，能否比统一规则更准确、及时地区分有意点击、保持、松开和普通调整动作，并减少点击对定位的干扰。

先继续使用 MediaPipe 获取关键点。它提供21点位置和左右手分类；估计深度不是接触或压力传感器，左右手分类分数也不能直接作为每个关键点的可见度。[MediaPipe 输出说明](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python)

实施顺序：

1. **先标注失败。** 记录连续关键点序列、任务目标和人工标注的动作开始/结束；包含无意动作、遮挡、松手、重新接管等负例，不只收集标准成功手势。
2. **建立公平的简单基线。** 比较统一规则、个人统计校准、几何特征 RF/SVM。调参只使用训练/验证数据。
3. **有时序证据后再训练小模型。** 用仅看当前与过去帧的1D-CNN/TCN等预测动作阶段，报告时间窗口带来的延迟。TCN 是序列建模候选，不保证在本项目优于规则或 RF/SVM；参考 [Bai 等人的原论文](https://arxiv.org/abs/1803.01271)。
4. **离线通过后以旁路方式验证。** 模型先只记录建议结果，对比实际动作，不直接控制鼠标；通过事件级与真人任务评估后，再接入既有状态机。

这里的“训练 CNN”优先指训练关键点序列上的小模型，不是从零重新训练整套相机图像到手部关键点的视觉网络。只有数据证明底层关键点跟踪是主要瓶颈，且具备匹配的标注和计算资源时，才考虑更换/微调视觉模型。

第二优先级可以是学习可靠性评分、个人差异或点击引起的位移补偿，但每项都需要相应标签。轨迹去噪若没有可信目标轨迹，就不能假装已有监督信号；也不宜用“预测用户想点哪里”掩盖不稳定定位。紧急停止、按键生命周期和输入超时继续由确定性逻辑管理。

## 7. 体验实验与数据协议

### 固定任务

先在可控练习区比较小/中/大目标点击、同位置双击、指定区域拖拽、短距离反向细调、长距离移动和滚动停止，再在浏览器、文件管理器等常用应用试用。日常任务与实验任务分开标注；真实用户输入或保密内容不进入研究日志。

同一人交替使用各模式，轮换顺序、给予相同练习时间，记录设备、屏幕缩放、光照、机位、惯用手和支撑姿势。比较新用户泛化时按参与者划分；比较个人适应时用独立场次。不能把同一段连续录制的相邻帧随机分到训练和测试两侧。

### 需要报告的指标

| 维度 | 指标与解释 |
|---|---|
| 精度 | 静止轨迹范围/方差、点击落点偏移、小目标命中率、反向细调偏差 |
| 速度 | 目标完成时间、动作到事件延迟、跟踪/处理耗时分布、恢复耗时 |
| 错误 | 误触频率、漏触比例、双击成功率、拖拽意外中断、错误换手与恢复失败 |
| 动作成本 | 手部轨迹长度、重新接管次数、额外解锁动作、明显手臂移动次数 |
| 舒适度 | 固定时长后的主观费力度、疲劳与偏好，记录前臂是否支撑 |
| 运行 | 崩溃、卡键、丢流、异常跳动、平台/应用兼容性 |

单独保存分母和事件定义，例如误触按有效使用时间计，漏触按人工标注的有意点击计。报告每位参与者与总体结果，不用大量相关帧伪装大量独立样本。若数据足够，再给出适当的不确定性区间。

先用基线和小规模试测确定有实际意义的改善幅度及可接受退步范围，随后固定验收标准再看最终测试集。本计划不预填尚未测出的准确率、延迟或疲劳改善百分比。

### 隐私与保存

默认日常日志继续只保存本地性能/状态摘要；开启关键点序列、轨迹或标签采集时，应清楚说明内容、用途、目录和删除方式，并取得参与者同意。默认不保存摄像头图像、桌面截图、窗口内容或输入文本，不上传原始数据。

参与者使用编号；实验数据、个人参数和模型产物不自动进入 Git 或交付包。采集后的关键点仍属于参与者数据，应规定保留期限和访问范围；课程展示优先使用汇总图表或明确同意的示例。合成数据必须有来源标记。

## 8. 从实验版进入稳定试用版

- 保留稳定版本与实验版本的清晰版本号、配置和反馈记录；打包产物记录源码版本、依赖与校验值。
- 新模式有经典回退，个人校准可撤销。v0.9 全新配置默认精细；已有旧版设置但缺少模式字段时迁移为原版，保留此前手感；已保存的新版模式照常恢复。
- 自动测试覆盖输出有限值、边界、模式切换、停流、失手、松键、重新接管等行为；离线演示不打开摄像头或注入系统输入。
- 真人验收完成后，再做数日的实际试用，记录影响工作的问题；短演示成功不等于稳定日用。
- Mac、Windows 分别验证摄像头、权限、输入、双击、DPI与长时间运行；多屏要处理负坐标、不同缩放及重新连接，不仅是扩大坐标范围。
- 每次发布明确哪些是代码检查、合成测试、平台真机或真人体验结果；旧归档不覆盖，新构建不能继承旧版的验收结论。

下一步进行本人三模式及校准前后体验反馈，依据结果决定最值得继续打磨的移动/点击问题，同时准备可用于课程研究的数据协议。可靠恢复、多屏与包装易用性按实际日用阻碍逐步补齐。
